## ЧаВО (FAQ) для разработчиков

**В**: У этого мода открытый исходный код?  
**А**: [Да.](https://github.com/VidTu/HCsCR) (Доступный под лицензией
[Apache 2.0 License](https://github.com/VidTu/HCsCR/blob/main/LICENSE))

**В**: Я - владелец сервера. Я хочу заблокировать этот мод, как это сделать?  
**А**: Мод регистрирует
[plugin channel](https://minecraft.wiki/w/Java_Edition_protocol/Plugin_channels)
под ID `hcscr:imhere`. Старые версии использовали другой канал, но namespace -
всегда `hcscr`. *ВНИМАНИЕ*: Другие моды, схожие с этим, не предлагают способа
себя заблокировать. Попробуйте вложить своё время/ресурсы в плагин анти-чита,
если хотите заблокировать каждый из таких оптимайзеров.

**В**: Как скомпилировать под одну версию Minecraft?
Я устал ждать инициализации проекта часами.  
**А**: Запустите скрипт `./compileone <версия>-<загрузчик>` с нужной версией,
например: `./compileone 1.16.5-fabric`. Из-за требований Stonecutter, последняя
версия может тоже инициализироваться, из-за того, что она по задумке является 
[версией VCS](https://stonecutter.kikugie.dev/wiki/glossary#vcs-version).

**В**: Почему так много ненужного базара в этом README?  
**А**: ~~Я заплатил за всю LLM, я буду использовать всю LLM.~~
Писать README проще, чем писать нормальный код.

**В**: Используется ли AI/LLM/Code Generation/Copilot/etc.?  
**А**: [Возможно](https://github.com/VidTu/HCsCR/commit/1fd405d66e447c2dbdb775a39e3ca066b20e2fc4),
но не [без последствий](https://github.com/VidTu/HCsCR/commit/1898f1dc49a3b9e154cc89b40652a5cb30ef8459).
В общем и целом, нет, код написан людьми на 99.67%, потому что AI генерирует
абсолютную тупость, особенно для Minecraft. Если вы (или какие-либо
контрибьюторы) смогут использовать AI и он магически® заработает™,
то я рад за вас. Я не продвигаю AI, но я и не против его использования.

**В**: У HCsCR есть публичное API?  
**А**: Неа. Кроме упомянутого plugin channel, никаких публичных API в моде
нет. По этой причине, все классы/пакеты дополнительно помечены
[@ApiStatus.Internal](https://javadoc.io/static/org.jetbrains/annotations/26.1.0/org/jetbrains/annotations/ApiStatus.Internal.html).

**В**: А я могу забить и всё равно использовать этот мод при компиляции?
Что насчёт системы версий [SemVer](https://semver.org/lang/ru/) в этом моде?  
**А**: Можете, на свой риск. Система версий SemVer используется для
простоты, но она используется не по задумке. У мода нет публичного
API, и поэтому несовместимые изменения исходников/бинарников могут
и будут происходить даже между минорными и патч версиями.

## Сборка (Компиляция)

### Одна версия

> [!TIP]
> Это самый быстрый метод компиляции. Он может быть
> полезен, если вы хотите собрать мод всего для
> одной версии Minecraft для личного использования.
>
> Может занять от 15 до 30 минут на медленных
> устройствах (например, на GitHub CI).

Для сборки мода для одной версии Minecraft из исходного кода:

1. Требуется 4 ГБ свободной RAM, 10 ГБ свободного места
   на диске и активный доступ к интернету.
2. Установите Java 25 (для Gradle; для компиляции так же возможно нужны 8,
   17 или 21, скачайте любую, другая будет автоматически скачана через
   Java toolchains) и закиньте её в `PATH` и (или) `JAVA_HOME`.
3. Склонируйте или скачайте репозиторий. (папка `.git` *не* требуется)
4. Выполните в терминале/PowerShell команду `./compileone <версия>-<загрузчик>`.
   внутри папки скачанного репозитория. (например: `./compileone 1.16.5-fabric`)
5. Заберите JAR-ник из папки `./build/libs/`.

### Поддерживаемые версии

> [!NOTE]
> Это обычный метод компиляции, используемый при нормальной
> разработке и тестировании. Тем не менее, он не включает
> в компиляцию версии, помеченные как "Архаичные".
>
> Может занять от 30 до 60 минут на медленных
> устройствах (например, на GitHub CI).

Для сборки всех [Бета и Активных](#версии)
поддерживаемых версий мода из исходного кода:

1. Требуется 6 ГБ свободной RAM, 20 ГБ свободного места
   на диске и активный доступ к интернету.
2. Установите Java 25 (для Gradle; для компиляции так же будут нужна
   21, скачайте любую, другая будет автоматически скачана через
   Java toolchains) и закиньте её в `PATH` и (или) `JAVA_HOME`.
3. Склонируйте или скачайте репозиторий. (папка `.git` *не* требуется)
4. Выполните в терминале/PowerShell команду `./compileall`
   внутри папки скачанного репозитория.
5. Заберите JAR-ники из папки `./build/libs/`.

### Все версии

> [!IMPORTANT]
> Это самый медленный метод компиляции, нерекомендуемый для
> общего использования, если только вам не нужны *все* артефакты
> для всех поддерживаемых версий (включая "Архаичные") версии.
>
> Может занять **около 2 часов** на медленных
> устройствах (например, на GitHub CI).

Для сборки всех [Бета, Активных и Архаичных](#версии)
поддерживаемых версий мода из исходного кода:

1. Требуется 8 ГБ свободной RAM, 30 ГБ свободного места
   на диске и активный доступ к интернету.
2. Установите Java 25 (для Gradle; для компиляции так же будут нужны 8,
   17 и 21, скачайте любую, другие будут автоматически скачаны через
   Java toolchains) и закиньте её в `PATH` и (или) `JAVA_HOME`.
3. Склонируйте или скачайте репозиторий. (папка `.git` *не* требуется)
4. Выполните в терминале/PowerShell команду `./compileall --legacy`
   внутри папки скачанного репозитория.
5. Заберите JAR-ники из папки `./build/libs/`.

## Разработка/Отладка/Дебаггинг

Выполните команду `./launch <версия>` (например, `./launch 1.16.5-fabric`)
для запуска игрового клиента. К этому процессу можно подсоединить отладчик.
Поддерживается хот-свап. "Улучшенный" хот-свап (class redefinition) и
хот-свап агент будут работать, если это поддерживается вашей JVM.

Переключайтесь между текущей версией Stonecutter используя команду
`./switch <версия>`. Не рекомендуется изменять закомментированный
препроцессором код, лучше переключитесь на нужную версию.

Перед коммитом изменений, сбросьте версию Stonecutter
командой `./reset` во избежание бардака в diff.

Запуск клиента через сгенерированные задачи (например, для IntelliJ IDEA), может
быть, работает, но скорее всего вам нужно будет что-то подчинить. Запуск игры
напрямую (в обход Gradle) тоже может заработать, но это тоже не поддерживается.

Среда разработки более строгая, тут есть: проверки Mixin, детектор Netty,
assert-ы Java и т.д. Код с багами, скорее всего, сломается быстрее тут, чем
на продакшне.

Рекомендуемая IDE для разработки - IntelliJ IDEA (Community или Ultimate)
с плагином Minecraft Development. Тем не менее, это не строгое требование.
Любая IDE/редактор будет работать нормально.

### Отладочные JAR-ники

Логическая опция (boolean property) для Gradle `ru.vidtu.hcscr.debug`
позволяет создавать более отладчиваемые JAR-ники.
Она контролирует следующие "под-опции":

- `ru.vidtu.hcscr.debug.javac`: Заставить `javac` выдавать данные
  `-parameters` для reflection. Рефлективные данные включают флаги и имена
  параметров методов, что может быть полезно для отладки или декомпиляции.
- `ru.vidtu.hcscr.debug.metadata`: Не использовать свой пост-процессор
  (смотрите папку `buildSrc`) для удаления аннотаций и других метаданных
  из класс-файлов. (например, атрибутов `SourceFile` и тегов `@deprecated`)
- `ru.vidtu.hcscr.debug.asserts`: Оставить декларации `assert` после
  компиляции для улучшенной отладочности. На заметку: assert-ы должны быть
  включены используя флаг VM `-enableassertions` на большинстве JVM.
- `ru.vidtu.hcscr.debug.logs`: Изменить вызовы логгирования:
  - Включить `debug` и `trace` вызовы логгинга и создавать для них логгеры
    в местах, где логгеры не создаются при обычном исполнении кода.
  - Добавить маркер `MOD_HCSCR` к каждому вызову логгирования.
  - Всегда показывать стак-трейсы для ошибок (исключений).
  - Показывать больше деталей в логах. (больше контекста, параметров и т.д.)
- `ru.vidtu.hcscr.debug.resources`: Не уменьшать файлы ресурсов, которые *не*
  являются классами Java, такие как файлы `.json`, `.toml`, `.mcmeta` и другие.
- `ru.vidtu.hcscr.debug.package`: Не удалять файлы `package-info.class`.

Более точечные опции имеют приоритет над глобальной.
Все опции отладки *отключены* по умолчанию. Смотрите
[документцию Gradle](https://docs.gradle.org/current/userguide/build_environment.html#sec:project_properties)
для подробностей о том, как ставить опции Gradle.

Например, вы можете собрать "JAR-ник со всеми опциями отладки",
используя `./gradlew -Pru.vidtu.hcscr.debug=true assemble`.

### Мелкие JAR-ники

> [!WARNING]
> **Заметка**: Из-за этой опции вам *будет* сложнее понять, какие части мода
> вызывают проблемы. *Не* включайте её, если вы не знаете что вы делаете!

Если вы хотите мега-маленькие JAR-ники за счёт возможности отладки, вы
можете установить логическую опцию Gradle `ru.vidtu.hcscr.slim` на `true`.

Эта опция несовместима с опциями "Отладочных JAR-ников".
